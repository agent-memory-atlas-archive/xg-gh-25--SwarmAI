## 9. Lessons
- [pitfall] 一个靠 agent-discipline 顺序保证的不变量(deliver.md: seed-lessons→run-report→run-commit)在崩溃恢复/手工补流程下必然失效——把保证从 prose 挪进 run-commit 代码(缺失即 auto-gen,仍缺才 fail-loud)才是结构性根治,而非再写一条流程提醒。
- [decision] fail-loud 的正确 severity 是 fail-SAFE 而非 hard-block 恐慌:auto-gen 失败 sys.exit(2) 在任何 git add 之前,commit 没发生、无数据丢失,re-run 即可——所以 transient-fault 下阻断一个合法 commit 是可接受代价,不需要 auto-retry(瞬时错该浮现给人,不该静默重试)。
- [principle] 一个为『让违反可见』而设计的修复,若成功路径不发信号就只是静默 paper-over——auto-gen 成功必须在 warnings 通道留一条非-阻断通知,否则 operator 看不出 ordering 被滑过;可观测性是这类 self-heal 修复的一等交付物,不是附带品。
