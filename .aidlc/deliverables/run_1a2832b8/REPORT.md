## 9. Lessons
- [pitfall] A controlled <details open={prop}> is a footgun: a prop-driven open silently REOPENS a panel the user collapsed, or force-closes one they are reading. Make it genuinely controlled (local open state + onToggle) and only auto-transition on a specific edge (streaming→historical via a wasStreaming ref), never on every render.
- [decision] For a tool/group collapse whose expansion must survive a content shift (load-older prepend / stream-end reconcile), key the expansion Set by a CONTENT-STABLE id (first member identity) NOT the positional startIndex — a positional key re-points a user-opened group at a DIFFERENT run after any index shift, which reads as a correctly-persisting but wrong-group expansion.
- [pitfall] A React list element carrying LOCAL state (a collapsible sub-component) must have a key prefixed by its TYPE, not a bare positional index shared with sibling types — a thinking block keyed cb-${i} can reuse a text block instance at the same index and leak its open-state. Distinct prefix (th- vs cb-) makes the slot un-shareable.
- [pitfall] A summary-label built as verb+noun from two maps double-nouns when the verb already embeds the noun (CATEGORY_LABELS skill=Ran skill + CATEGORY_NOUN=skills → Ran skill 2 skills). Keep verbs PLAIN (action only) and nouns separate; a test that asserts the double-noun output has frozen the bug as expected-value (C044) — fix both.
- [decision] When a backend emits TWO distinct non-empty sentinels for the same unknown case (unknown vs fallback), normalize them to ONE key at the grouping boundary, else two adjacent identical-looking rows refuse to merge — normalize where the key is READ, not at every producer.
