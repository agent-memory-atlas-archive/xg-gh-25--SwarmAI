## 9. Lessons
- [principle] 一个 commit-gate 的 fail-open 必须区分 store-UNREADABLE 和 store-EMPTY: 两者若都返回空集, infra 故障(dir 不可读)就伪装成"没人审"而误 refuse — 把 bug 变成 self-lock. 修法: 不可读返回 None(fail-open 信号), 可读但空返回 set()(真零覆盖). is_dir() 返回 False 不抛异常, 所以 try/except 捕不到这个 case.
- [principle] 一个 --force/override 旁路如果不留审计痕迹, 就把它要防的违规"正常化"了: forced-skip 的 commit 与合规 commit 字节级不可区分. 任何 override 一个质量 gate 的路径, 必须在 override 发生时写一条可查的 intervention 记录 + 大声 WARN, 否则 gate 形同虚设(lazy IC 学会无痕 --force).
- [guideline] 归一化必须双侧对称: 当写入侧强制一个格式(marker expert_id 被正则 [a-z][a-z0-9-]* 强制小写), 读取侧的比对也必须施加同样的归一化(.strip().lower()), 否则大小写/空白差异造成 false self-lock. 对称性要有 mutation 测试锁(撤一侧 .lower() → 跨大小写测试 RED).
- [correction] 声明 required_experts 时诚实声明"真会 dispatch 的", 而非"方便通过 gate 的": Gate-1 挑我 drop state-machine 是 tailoring declaration(D7 要防的那个动作). 正解是声明全部真相关的(correctness+security+state-machine)并真 dispatch 三个 — 让 D7 第一次 enforce 就是它自己的 commit.
- [pitgall] pipeline 的 publish/advance 有逐 stage 的 schema 校验(build 要 tdd{green_pass,smoke_tests}+ac_coverage{impl,verified,plan_ac_ref}; review 要 litmus_gate{verdict,hf_checked,evidence}+integration_trace+runtime_patterns), 用 keystone 已过的结构做模板比反复试错快 — 别用薄 data 撞严 schema.
